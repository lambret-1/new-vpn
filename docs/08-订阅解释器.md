# 08 - 订阅解释器

## 8.1 职责

- HTTP 拉取订阅文本
- Base64 自动识别 + 容错解码
- 分行处理，注释行提取流量 / 过期元信息
- 识别 `vmess://` / `vless://` 链接
- 单链接解析，输出 `RawNodeModel`
- 过滤规则执行
- 收集解析失败行

> 只负责解析，不操作持久化存储。输出交给订阅管理器 → 节点模块增量同步。

## 8.2 整体流程

```
HTTP 拉取 → Base64 检测解码 → 分行处理 → 注释行提取 meta
    → 逐行解析 vmess/vless 链接 → 过滤规则 → 输出 SubParseResult
```

## 8.3 数据模型

```swift
struct SubParseResult {
    let success: Bool
    let rawContent: String
    let metaInfo: SubscriptionMetaInfo
    let parsedNodeList: [RawNodeModel]
    let failItems: [SubParseFailItem]
    let parseTimeMs: Int
}

struct RawNodeModel {
    let protocolType: String
    let host: String
    let port: Int
    let uuid: String
    let alterId: Int?
    let security: String?
    let transportType: String?
    let path: String?
    let wsHost: String?
    let tlsEnable: Bool
    let sni: String?
    let reality: Bool
    let publicKey: String?
    let shortId: String?
    let remark: String
}

struct SubParseFailItem {
    let rawLine: String
    let errorMsg: String
    let lineNumber: Int
}
```

## 8.4 Base64 解码

### 检测逻辑

1. 去除换行、空格
2. 判断字符集合是否符合 Base64 字符集
3. 尝试解码
4. 解码成功：使用解码后明文
5. 解码失败：判定为明文，直接使用原始 body

### 容错处理

- 补齐缺失的 `=` 填充
- 处理换行混杂的 Base64
- 处理 URL Safe Base64（`-` `_` 替换为 `+` `/`）

## 8.5 注释行 Meta 解析

常见订阅格式：

```
# upload: 10GB
# download: 90GB
# total: 100GB
# expire: 2026-12-31
```

正则宽松匹配：

- `total|流量|总流量` → 总流量
- `upload|download|上传|下载` → 已用流量
- `expire|到期|过期` → 到期时间

解析不到则置 0。

## 8.6 链接解析

### vmess://

1. 去掉 `vmess://` 前缀
2. Base64 解码
3. 解析 JSON
4. 映射 `RawNodeModel`

### vless://

1. 去掉 `vless://` 前缀
2. URL 解析
3. 用户信息部分 → uuid
4. host、port
5. Query 参数 → transport、tls、reality
6. 锚点（`#` 后）→ remark

## 8.7 过滤规则

对解析成功的节点列表执行：

1. `excludeProtocol`：剔除指定协议
2. `excludeKeyword`：节点名称包含关键词则剔除
3. `onlyIncludeKeyword`：只保留名称命中关键词的节点

## 8.8 容错策略

- 单条节点损坏不导致整个订阅失败
- 某一行链接解析错误，记入 `failItems`
- 继续解析剩余行
- 网络异常：超时、404、403、500，返回失败
- 订阅返回空内容：`parsedNodeList` 为空
- 超大订阅：超过大小上限直接终止
